## What Went Well

1. Scope discipline was strong across the epic.
   - Each story delivered only its intended slice.
   - Persistence, edit, complete, delete, and important-task behavior were correctly deferred to later epics.

2. UI quality stayed consistent.
   - The Warm Minimal visual direction was preserved.
   - CSS custom properties, distinctive typography, responsive layout, focus states, and subtle interaction polish were applied throughout.

3. Architecture consistency improved story by story.
   - Task schema remained aligned with the architecture.
   - Runtime state stayed centered around a single in-memory task array.
   - Rendering remained DOM-safe and avoided raw HTML insertion for user task titles.

4. Testing and verification were effective.
   - Build checks passed for each story.
   - Browser verification was performed for UI behavior.
   - Node tests were added where practical for task, validation, and render contract behavior.

5. Security-sensitive rendering was handled well.
   - User-provided task titles were rendered with safe text APIs.
   - HTML-like task titles were manually verified as literal text.

## Challenges and Lessons Learned

1. Dependency maintenance remains separate from feature delivery.
   - Story 1.1 noted moderate Vite audit advisories.
   - The team intentionally avoided `npm audit fix --force` because it could cause a major-version upgrade outside story scope.

2. DOM behavior is harder to test without browser-like dependencies.
   - Story 1.4 initially exposed that Node's built-in test environment has no DOM.
   - The team adapted by extracting a pure `createActiveTaskViewModel(task)` helper for dependency-free render contract tests.

3. Browser verification is essential for this project.
   - Several acceptance criteria involve focus behavior, responsive layout, keyboard flow, visible validation, and DOM-safe rendering.
   - Automated checks alone are not enough for UI acceptance.
